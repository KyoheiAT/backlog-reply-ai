# Backlog AI Reply

Backlogの課題画面で、日本語の返信下書きを作成するChrome拡張です。課題本文・コメント・指定した関連課題を読み、GitHub CopilotまたはChatGPTのCodexを使って、返信案をBacklogのコメント入力欄に入れます。

**AI用のAPIキーは不要です。課題情報の取得にはBacklog APIキーが必要です。** 投稿・通知先の選択・課題の状態変更は行いません。生成後に内容を確認して、利用者が投稿します。

## 主な機能

- GitHub Copilot／ChatGPT Business（Codex）の切り替えと、サービス別のモデル選択。
- 返信の新規作成、入力した下書きの文章整理、要点整理。
- 同じスペース内の別課題・プロジェクトの参照と、Backlog MCPによる追加調査。
- 本人情報とBacklog公式ガイドに基づく共通プロンプトの生成・編集・固定。
- 返信先プロジェクトの設定に合わせたMarkdown記法／Backlog記法の切り替え。
- 折りたためるAIパネル、処理状況と所要時間の表示、既存の下書きの置き換え確認。

## 必要な環境

| 項目 | 要件 |
| --- | --- |
| OS・ブラウザー | Windows版Google Chrome 120以上。現在のセットアップはWindows・Google Chrome専用です。 |
| Node.js | 22.12以上。`node`・`npm` をPowerShellから実行できること。 |
| PowerShell | Copilot CLIの公式要件は6以上です。導入作業にはPowerShell 7を推奨します。 |
| .NET Framework | 初回登録で使用する4.xのC#コンパイラー（`csc.exe`）。 |
| Backlog | 対象の課題を閲覧できるアカウントと、そのアカウントのAPIキー。 |
| AI | 以下のどちらかを利用できるアカウントと、対応するCLIへのログイン。 |
| 通信 | Backlog・選択したAIサービスへのインターネット接続。 |

| AIの選択肢 | ローカル接続 | 認証 |
| --- | --- | --- |
| GitHub Copilot | GitHub Copilot SDK | Copilot CLIからGitHubアカウントでログイン |
| ChatGPT Business（Codex） | Codex CLI | Codex CLIからChatGPTアカウントでログイン |

両方を用意すると設定で切り替えられます。一方だけ利用する場合は、そのCLIだけを導入してください。利用可能なモデル・利用枠はアカウントや組織の設定に従います。本アプリはCodexのChatGPTログインを確認しますが、Businessというプラン名自体を判定しているわけではありません。ChatGPT画面のGPTsや会話を呼び出す仕組みではなく、アプリのプロンプトで新しい生成を行います。

対応する課題URLは `https://your-space.backlog.com/view/PROJECT-123` です。`backlog.jp`・`backlogtool.com` も対象です。独自ドメイン・オンプレミス環境には対応していません。生成できるのは、設定画面で登録したBacklogスペース（APIキーの発行元）の課題だけです。

## 導入手順

### 1. ソースを取得する

今後も使う場所にリポジトリを配置し、PowerShellでそのフォルダーを開きます。

```powershell
git clone https://github.com/KyoheiAT/backlog-reply-ai.git
cd backlog-reply-ai
npm ci
```

Gitを使わない場合は、GitHubの **Code → Download ZIP** からダウンロードして展開し、`package.json` があるフォルダーで `npm ci` を実行してください。

### 2. 利用するAIにログインする

**GitHub Copilotの場合**

```powershell
winget install GitHub.Copilot
copilot login
```

表示される手順に従ってGitHubアカウントでログインします。インストール直後に `copilot` が見つからない場合は、PowerShellを開き直してください。組織の契約では、管理者がCopilot CLIの利用を許可している必要があります。

公式資料：[Copilot CLIのインストール](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)、[認証](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli)

**ChatGPT Business（Codex）の場合**

```powershell
npm install -g @openai/codex
codex login
codex login status
```

ChatGPTアカウントでログインしてください。本アプリではOpenAI APIキーによるCodex認証を使用しません。

公式資料：[Codex CLI](https://learn.chatgpt.com/docs/codex/cli)、[CLIの認証](https://learn.chatgpt.com/docs/auth?surface=cli)

### 3. Chromeに拡張を追加する

1. Chromeで `chrome://extensions` を開きます。
2. 右上の **デベロッパー モード** をONにします。
3. **パッケージ化されていない拡張機能を読み込む** を押します。
4. このアプリの **`manifest.json` があるフォルダー** を選択します。`bridge` や `node_modules` ではありません。
5. 追加された **Backlog AI Reply** のカードに表示される、32文字の拡張IDをコピーします。

### 4. ローカル接続を登録する

アプリのフォルダーで、次の `ここにコピーした拡張ID` を実際のIDに置き換えて実行します。

```powershell
npm run setup -- --extension-id ここにコピーした拡張ID
```

通常、管理者権限は不要です。Chromeがこのアプリを起動できるよう、利用中のWindowsユーザーに登録します。

登録後、`chrome://extensions` で拡張を再読み込みし、**詳細 → 拡張機能のオプション** を開いて、**自動起動と接続をテスト** を押してください。オプション画面にも実際の拡張IDを入れた登録コマンドを表示しています。

このテストが確認するのはローカル処理の起動と通信です。AIへのログイン・契約・モデルの利用可否・文章生成までは確認しません。登録前にオプションを開いてモデル一覧の取得に失敗した場合は、登録後に設定画面を読み直してください。

**以後、毎回 `npm start` を実行したり、ターミナルを開いたままにしたりする必要はありません。** Chromeが操作ごとにローカル処理を自動起動し、終了後に接続を閉じます。常駐や、Chrome起動から終了までプロセスを維持する方式ではありません。

### 5. Backlogとモデルを設定する

オプション画面の上側のフォームを入力し、**設定を保存** を押します。

| 設定 | 内容 |
| --- | --- |
| 利用するAI | GitHub CopilotまたはChatGPT Business（Codex）。初期値はCopilotです。 |
| Copilotモデル／Codexモデル | 初期値は自動選択。**一覧を更新** で候補を取得し、**モデルIDを直接指定** で手入力できます。選択はサービスごとに保存します。 |
| Backlog APIキー | Backlogの個人設定で、このアプリ専用のキーを発行して入力します。メモ欄に用途を書いておくと、不要になったときにこのキーだけを削除できます。 |
| BacklogスペースURL | 必須。APIキーを発行したスペースのURLです。例：`https://your-space.backlog.com`。APIキーはこのスペースにだけ送信し、別のスペースの課題画面ではAPIキーを送らずに生成を中止します。 |
| 取得する直近コメント件数 | 現在の課題の直近1〜100件。初期値は50件です。 |
| プロンプトのテスト | 初期状態はOFF。詳細は後述の比較テストを参照してください。 |

APIキーの発行方法：[Backlog公式ガイド](https://support.nulab.com/hc/en-us/articles/8783772200217-How-to-register-SSH-public-and-API-keys-in-Backlog)

モデル一覧の取得では文章を生成しません。一覧に出るモデルでも、利用枠や組織の設定によって生成時に利用できない場合があります。

本人情報を使う場合は、下側の **共通プロンプトと本人情報** に表示名・任意のプロフィールURLを入力して、**プロンプト設定を保存** を押します。上側とは保存ボタンが別です。初期状態の標準プロンプトは、再生成を行う前から利用できます。

最後に、開いているBacklogの課題タブを再読み込みしてください。

## 日常の使い方

1. Backlogの課題画面で、コメント入力欄付近の **AI返信** を開きます。
2. **作成モード** を選び、**今回伝えたい内容** に要点・依頼・下書きなどを入力します。
3. 必要に応じて、追加で参照する課題・プロジェクトを指定します。
4. **AIで返信文を生成** を押します。作業ログで処理状況と時間を確認できます。
5. 生成文に、今回の入力にも現在のBacklogスペースにもないURL（リンク・画像）が含まれる場合は、挿入前に確認が表示されます。課題やコメント内の指示で混入した可能性があるため、宛先を確認してから承認してください。
6. コメント欄に既存の文章がある場合は、置き換え確認が表示されます。承認すると生成結果で置き換え、キャンセルすると元の文章を保ちます。
7. 入力された下書きを確認・編集し、Backlogの操作で投稿します。通知先や状態変更も必要に応じて自分で設定します。

**今回伝えたい内容** は最大10,000文字です。意図を明示すると、次のように使い分けられます。

| やりたいこと | 入力例 |
| --- | --- |
| 相手への返信を作る | `直近の質問に返信して。修正は検証環境へ反映済み、本番反映日は未定。検証環境での確認をお願いしたい。` |
| 自分の下書きを整える | `以下の返信案を柔らかく整えて。` に続けて下書き全文を入力 |
| 要点を整理する | `課題の経緯から、決定済みのことと確認が必要なことを整理して。` |

自分の文面全文だけを入力した場合は、明示的な対象指定がなければ、その文面を整える扱いです。相手から届いた文章に返信したい場合は、**「以下の相手の文に返信して」** と添えてください。今回の明示的な依頼や追加指示で対象を指定した場合は、その指定を優先します。

AIパネルは初期状態で小さく折りたたまれ、半透明で表示されます。生成中も開閉できます。**参照した情報** も初期状態は折りたたみです。作業ログには取得・生成などの処理状況と0.1秒単位の時間を表示し、モデルの内部思考は表示しません。AIパネルの入力内容やモードはページ内で保持しますが、ページを再読み込みするとリセットされます。

## 参照範囲とエージェントモード

**追加で参照する課題・プロジェクト（任意）** に、同じBacklogスペース内の課題キー・プロジェクトキー・対応URLを指定できます。空白・改行・カンマで区切り、課題は5件、プロジェクトは3件まで、入力全体は2,000文字までです。

```text
PROJECT-123
PROJECT-456
OTHER_PROJECT
https://your-space.backlog.com/view/OTHER_PROJECT-789
```

| モード | 取得する情報 |
| --- | --- |
| 通常の返信作成 | 現在の課題と設定件数のコメント、指定した別課題の本文と各直近20コメントまで、指定したプロジェクトの情報と更新順の最近10課題の概要をまとめて取得します。 |
| エージェント（Backlog MCPで調査） | 現在の課題とコメントを起点に、AIが必要な情報を判断し、許可した範囲でBacklog MCPから追加取得します。追加調査は最大6回です。 |

エージェントの **同じプロジェクト内の他課題も調査する** は初期状態でONです。OFFにすると、現在のプロジェクト全体を自動的に調査範囲へ加えません。ただし、参照欄で明示した課題・プロジェクトは引き続き対象です。このチェックは通常モードには影響しません。

エージェントが使えるのは、プロジェクト情報・課題検索・課題詳細・コメントの読み取りだけです。書き込み操作は許可しません。追加調査の判断にAIを複数回利用するため、通常モードより時間や利用枠を使う場合があります。参照対象の添付ファイル本体は取得しません。

## 共通プロンプトと記法の設定

### 生成プロンプトと追加指示

| 項目 | 役割 |
| --- | --- |
| 本人の表示名・プロフィールURL | 返信を書く本人の識別情報です。相手の宛名として扱ったり、本人への自己メンションを加えたりしないよう指示します。 |
| 生成プロンプト | 日本語の文面編集・タスク判定・丁寧さ・事実保持・改行などの標準指示を含む主プロンプトです。直接確認・編集できます。最大12,000文字。 |
| 常に追加する指示 | 独自のルールを追加する欄です。初期値は空欄で、主プロンプトの再生成では変更しません。最大10,000文字。 |
| 保存済みの共通プロンプト全体 | 保存した設定から組み立てた内容を確認する読み取り専用欄です。未保存の編集は反映しません。 |

**保存して再生成** を押すと、本人情報とBacklog公式の操作・記法ガイドから補足を作り、標準指示と組み合わせて生成プロンプトを更新します。参照する公式資料は、課題と状態、お知らせ機能、プロジェクトの基本設定、Backlog記法、Markdown記法の5記事です。標準指示の本文はアプリ側で維持し、AIには補足部分を生成させます。

表示名が登録済みで固定がOFFの場合は、**Chromeの起動時にも自動再生成**します。設定画面を開くことや、拡張の再読み込みだけでは自動再生成しません。手動・自動ともに選択したAIの利用枠を使い、失敗した場合は以前の生成プロンプトを保ちます。

- **生成プロンプトを固定（起動時・手動の再生成を停止）**：直接編集した主プロンプトを維持したい場合にONにして保存します。固定中は手動の再生成も停止します。
- **生成プロンプトをデフォルトに戻す**：主プロンプト欄をアプリの標準指示に戻します。
- **追加指示を空に戻す**：追加指示欄だけを空にします。
- **プロンプト設定を保存**：編集・リセット・固定設定を保存します。リセットボタンを押しただけでは保存されません。
- **保存済みを読み直す**：未保存の編集を破棄し、保存済みの状態に戻します。

固定がOFFのまま再生成すると、直接編集した主プロンプトも置き換わります。繰り返し適用したい独自ルールは **常に追加する指示** に入れるか、主プロンプトを固定してください。以前の標準指示が追加欄に残っている場合は、必要な独自部分を控えたうえで、主プロンプトをデフォルトに戻し、重複する追加指示を整理して保存できます。

### Markdown記法／Backlog記法

Chrome起動時に保存済みのAPIキーとスペース情報から記法を確認し、**返信生成時は返信先プロジェクトのAPI設定を優先**します。別課題の記法や過去のコメントから推測して上書きしません。プロジェクトが明示的にスペース設定を継承する場合は、そのスペース設定を使います。設定の取得に失敗した場合や未知の値の場合は、プレーンテキストを使います。

**記法を再確認** は保存済みのスペースURL・APIキーを使います。変更した場合は、先に **設定を保存** を押してください。この確認ではAIを利用しません。

### 自分の直前の投稿を除外する比較テスト

過去に自分が送った返信をそのまま参照せず、同じ入力で生成を比較したい場合の機能です。

1. オプションの **プロンプトのテスト → テスト時に直近の自分のコメントを除外する** をONにします。
2. **設定を保存** を押して生成します。
3. 比較が終わったらOFFに戻して保存します。

APIキーの本人IDを使い、現在の課題で最後に投稿した本文のある自分のコメント1件を、AIへ渡す履歴から除外します。その後に別の人が投稿していても対象です。通常・エージェントの両方に適用し、MCPで再取得した同じコメントも除外します。Backlog上の投稿は変更しません。

この機能は過去の課題全体を再現するものではありません。課題本文や別コメントに引用された同じ文章までは除きません。対象の確認は100件ずつ最大10回まで行い、その範囲で除外すべきコメントの有無を確認できない場合は生成を停止します。

## データの扱いと接続の仕組み

```text
Backlogの課題画面
  └─ Chrome拡張 ── Backlog API（課題・コメント等を取得）
       └─ Native Messagingでローカル処理を起動
            ├─ Copilot SDK ── GitHub Copilot
            ├─ Codex CLI   ── ChatGPTのCodex
            └─ エージェント時：Backlog MCP ── Backlog API
```

- **保存先**：AI・モデル・Backlog APIキー・本人情報・共通プロンプトなどは、Chromeの拡張機能用ローカルストレージに保存します。GitHub／ChatGPTのログインは各CLIで管理し、拡張にAIの認証情報を入力しません。
- **返信時の送信内容**：課題・コメント・追加参照情報・今回の入力・本人情報・共通プロンプトなどを、選択したAIに送信します。失敗時にもう一方のAIへ自動送信しません。
- **プロンプト再生成時の送信内容**：Backlogの公開公式ガイドと本人情報を選択したAIに送信します。課題データやBacklog APIキーは使いません。
- **Backlog APIキー**：Backlogへの認証用です。設定したBacklogスペースURLのオリジンにだけ送信し、別のスペースや、同じドメインの別サブドメインには送りません。エージェント時はローカルのBacklog MCPにも渡しますが、AIプロンプトには含めません。
- **操作範囲**：Backlog情報の取得と、ブラウザー上の下書き作成に限定します。AIにはファイル操作・シェル実行を許可せず、エージェントのMCP操作も読み取り4種に限定します。
- **ローカル接続**：HTTPの待受ポートを開かず、登録した拡張IDからのNative Messagingを使います。ローカルで接続処理を動かしますが、モデルは各AIサービスで実行されます。

## 更新・移動・削除

### 更新する

Gitで取得した場合は、アプリのフォルダーで実行します。

```powershell
git pull --ff-only
npm ci
```

ZIPで取得した場合は、新しいソースへ更新して同じ場所で `npm ci` を実行します。その後、`chrome://extensions` で拡張を再読み込みし、設定画面とBacklogの課題タブも読み直してください。

BacklogスペースURLは必須です。以前のバージョンで未設定のまま使っていた場合は、更新後に設定画面でAPIキーを発行したスペースのURLを保存してください。

アプリの配置先・Node.jsの実行ファイルの場所・拡張ID・Codexの実行ファイルの場所が変わった場合は、**ローカル接続を再登録**してください。ランチャーの実装が更新された場合も、生成済みの実行ファイルを更新するため再登録が必要です。

```powershell
npm run setup -- --extension-id ここに実際の拡張ID
```

通常の更新で保存済み設定は維持されます。拡張を削除して追加し直すと設定を失うため、更新には拡張の再読み込みを使ってください。

### 配置フォルダーを移動する

1. Chromeで拡張を無効化します。
2. **移動前のフォルダー** で `npm run unsetup` を実行します。
3. フォルダーを移動し、新しい場所からChromeに読み込ませます。
4. 新しい場所から読み込んだ拡張のIDを確認し、新しいフォルダーで `npm run setup -- --extension-id ここに実際の拡張ID` を実行します。
5. 新しい方の拡張を有効にし、必要な設定を保存して、オプションから接続テストを行います。別の拡張カードとして追加された場合は、動作確認後に不要な旧カードを削除します。

別フォルダーにある既存登録を誤って上書きしない仕組みのため、先に旧登録を解除してください。読み込み直しで拡張IDが変わる場合に備え、必要なプロンプトなどは移動前に控えてください。

### 削除する

1. Chromeで拡張を無効化します。
2. アプリのフォルダーで `npm run unsetup` を実行します。
3. Chromeから拡張を削除します。
4. 不要になったアプリのフォルダーを削除します。
5. Backlogの個人設定の **API** で、このアプリ用に発行したAPIキーを削除します。拡張を削除しても、キー自体は有効なまま残ります。

`unsetup` は、このフォルダーを指すChromeの登録を解除します。GitHub／ChatGPTからのログアウト、BacklogのAPIキーの削除、アプリのフォルダー自体の削除は行いません。

## 困ったとき

| 状況 | 確認・対処 |
| --- | --- |
| AI返信が表示されない | 対応するドメインの課題URLか、拡張が有効かを確認し、課題タブを再読み込みします。 |
| `Receiving end does not exist` などの接続エラー | タブ復帰時に接続を回復する処理があります。更新直後などに続く場合は、拡張・設定画面・課題タブを再読み込みします。 |
| ローカル接続のテストに失敗する | 現在の拡張ID・配置先で `setup` を実行したか確認します。Node.jsやCodexの場所を変えた場合も再登録します。 |
| `node`・`npm`・`copilot` が見つからない | 必要なツールを導入し、PowerShellを開き直します。Node.jsは `node --version` で22.12以上か確認します。 |
| PowerShellが `npm.ps1` の実行を拒否する | コマンドの `npm` を `npm.cmd` に読み替えます。例：`npm.cmd ci`、`npm.cmd run setup -- --extension-id ここに実際の拡張ID`。 |
| セットアップで `csc.exe` が見つからない | Windowsの.NET Framework 4.xが利用できることを確認し、再度セットアップします。 |
| モデル一覧や生成で認証エラーになる | 選択したサービスに `copilot login` または `codex login` でログインし直します。Codexは `codex login status` も確認します。 |
| 接続テストは通るが生成できない | 接続テストはAIの認証を検査しません。CLIのログイン、利用枠、組織の利用許可、選択モデルを確認します。 |
| Backlog情報を取得できない | APIキーが有効か、対象スペースと一致するか、その本人に課題の閲覧権限があるかを確認します。 |
| 「APIキーを送信せずに中止しました」と表示される | 開いている課題のスペースが、設定画面のBacklogスペースURL（APIキーの発行元）と異なります。APIキーを発行したスペースの課題で利用するか、設定を見直します。 |
| プロンプトが自動更新されない | 本人の表示名、固定設定、CLIへのログインを確認します。設定画面を開くだけでは再生成しないため、必要なら固定を解除して **保存して再生成** を使います。 |
| 出力の文体が意図と違う | 利用モデル、今回の入力、保存済みの共通プロンプトを確認します。古い標準指示や独自指示が重複していないか、生成欄と追加欄を見直します。 |

<details>
<summary>Codexの場所が自動検出されない場合</summary>

公式CLIを導入したあとでも検出されない場合は、実際の絶対パスを指定して登録します。

```powershell
$env:CODEX_BIN = 'C:\実際の場所\codex.exe'
npm run setup -- --extension-id ここに実際の拡張ID
```

`codex.exe` のほか、公式npm版の `codex.cmd`・`codex.js` も指定できます。パスは登録時に保持されるため、実行ファイルを移動した場合は再登録してください。

</details>

## 開発・検証

```powershell
npm test
```

テストはAIへ送信せずに実行できます。実際のAIへの接続・生成を確認する場合は、使用するサービスのコマンドを実行します。

```powershell
npm run smoke:copilot
npm run smoke:codex
```

`smoke:*` はスクリプト内の架空の文面をAIへ送り、利用枠を消費します。実際のBacklog課題は取得しません。

| ファイル | 役割 |
| --- | --- |
| [manifest.json](manifest.json) | 拡張の定義・権限・対応URL |
| [content.js](content.js)・[content.css](content.css)・[panel-layout.js](panel-layout.js) | 課題画面のAIパネルとコメント入力 |
| [background.js](background.js)・[backlog-formatting.js](backlog-formatting.js)・[tab-recovery.js](tab-recovery.js) | Backlog取得、生成制御、記法判定、タブの接続回復 |
| [options.html](options.html)・[options.js](options.js) | 接続・モデル・Backlog設定 |
| [prompt-defaults.js](prompt-defaults.js)・[prompt-manager.js](prompt-manager.js)・[prompt-options.js](prompt-options.js) | 標準プロンプト、公式ガイドからの補足生成、編集画面 |
| [bridge/](bridge/) | Native Messagingホスト、AIプロバイダー、エージェント・MCPの制御 |
| [scripts/](scripts/) | Windows用の登録・解除、非表示ランチャー、接続検証 |
| [tests/](tests/) | 自動テスト |

エージェントの許可ツールは `get_project`・`get_issues`・`get_issue`・`get_issue_comments` です。Native Messagingホストの生成処理は最大180秒、拡張側の全体待機は最大240秒、同時生成は2件までです。

`npm start -- --extension-id <拡張ID>` は、旧HTTPブリッジ（`127.0.0.1:3210`）を起動する開発用の経路として残っています。拡張IDを指定しない場合は、使い方を表示して終了します。現在のChrome拡張はNative Messagingを使用し、このブリッジには接続しないため、通常の導入・利用には使いません。
