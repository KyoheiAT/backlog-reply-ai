# Backlog AI Reply — Chrome拡張

Backlogの課題本文・コメントや指定した別課題・プロジェクトを参照して、日本語の返信案を既存のコメント欄に挿入します。**GitHub CopilotとChatGPT Business（Codex）を設定で切り替えられます。モデルピッカーと、Backlog MCPで追加調査するエージェントモードを備えています。コメントは自動投稿しません。**

**AI用のAPIキーは不要です。Backlog APIキーは、課題・コメントを取得するために引き続き必要です。** GitHub／ChatGPTへのログインは公式CLIで行い、AIの認証情報をChrome拡張に入力しません。

**初回登録後は、生成ボタンを押すだけで使えます。毎回の`npm start`や、ターミナルの常時起動は不要です。** Chromeが必要なときにローカル処理を起動し、処理終了後に接続を閉じます。

## 仕組みと対応範囲

```text
Backlogの課題画面 → Chrome拡張 → Chromeがローカル処理を自動起動
                               （Native Messaging）
                                    ├─ Copilot SDK → GitHub Copilot契約
                                    └─ Codex CLI   → ChatGPT Business契約
```

- 設定で選んだサービスだけに送信します。エラー時に別サービスへ自動送信しません。
- Windows版Google Chrome向けです。常駐サーバー、待受ポート、Windows起動時の自動実行は不要です。[Chromeの公式な接続方式](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)を利用します。
- 返信生成時は、課題・コメント・指定プロジェクトの情報と今回の指示に、保存済みの本人情報・共通プロンプト・常に追加する指示を加えて、選択したAIへ送ります。エージェントモードでは、必要に応じて取得したBacklog情報も追加します。
- 共通プロンプトの再生成時は、Backlogの公開公式ガイドと本人情報を選択したAIへ送ります。課題データやBacklog APIキーは使いません。Chrome起動時の自動生成も契約の利用枠を消費します。
- 通常モードではBacklog APIキーを拡張内のGETリクエストだけに使用します。エージェントモードでは、ローカルのBacklog MCPプロセスにも認証用として渡します。AIへのプロンプトには含めません。
- 現在の課題は直近コメントを既定50件、最大100件取得し、AIには時系列順で渡します。添付ファイル本体は取得しません。
- 対応URLは `https://スペース名.backlog.com/view/PROJECT-123`、`backlog.jp`、`backlogtool.com`。独自ドメインやオンプレミス環境はこの版では対象外です。
- ローカル実行はAIのオフライン実行を意味しません。生成にはインターネット接続が必要です。

## Copilotはコード以外にも使える？

Copilot **Chat**には、現在もコーディング関連の質問を想定する説明があります。一方、Copilot **SDK**の公式な想定用途には自然言語対話と業務自動化が含まれ、公式ブログでも要約ツールなどの例が紹介されています。本拡張はSDKを使う自然言語の返信案作成アプリです。

これは「SDKなら制限が一切ない」という意味ではありません。モデルによる応答拒否、内容フィルター、利用上限、組織ポリシーは適用されます。

- [Copilot Chatの説明](https://docs.github.com/en/copilot/responsible-use/chat)
- [SDKの想定用途](https://docs.github.com/en/copilot/responsible-use/agents#4-intended-uses)
- [GitHub公式SDK紹介と利用例](https://github.blog/news-insights/company-news/build-an-agent-into-any-app-with-the-github-copilot-sdk/)

## CopilotとChatGPT Businessの比較

2026年10月27日に公式情報を確認しています。利用条件やモデルは変更されることがあります。

| 項目 | GitHub Copilot | ChatGPT Business（Codex） |
| --- | --- | --- |
| 使用方式 | 公式Copilot SDK 1.0.27 | 公式Codex CLIの非対話実行 |
| 認証 | Copilot CLIのGitHub OAuthログイン | Codex CLIのChatGPTログイン |
| モデル | 利用可能なClaude、GPT、Geminiなど | Codexで利用可能なOpenAIモデル |
| 消費する枠 | Copilot契約の利用枠 | ChatGPTのCodex利用枠 |
| VS Codeの常時起動 | 不要 | 不要 |
| 向く用途 | Claudeを継続したい、複数社のモデルを選びたい | ChatGPT Businessの業務環境にまとめたい |

APIキー不要でも無制限無料ではありません。Copilotは現在AI creditsが基本で、一部旧契約は従来方式が残ります。Codexにも利用上限があり、ChatGPT Workと利用枠を共有します。利用量・追加課金の設定は各契約で確認してください。

Copilot個人契約では学習利用設定を確認してください。Copilot Business／EnterpriseとChatGPT Businessは既定で業務データを学習に使用しません。生成内容を扱う会社・顧客の方針に合う契約を選んでください。

## 初回セットアップ（Windows）

### 1. Node.jsを用意する

[Node.js公式サイト](https://nodejs.org/)から **22.12以上（24 LTS推奨）** をインストールします。既存のNode.jsが古い場合は更新し、新しいターミナルを開いて確認します。

```powershell
node --version
npm --version
```

Copilot CLIを使うWindows環境ではPowerShell 6以上が必要です。通常はPowerShell 7を使ってください。`npm.ps1`の実行がポリシーで止まる場合は、以下の`npm`を`npm.cmd`に読み替えられます。

自動起動用の小さなプログラムの作成には、Windowsの.NET Framework 4.xを使用します。通常のWindows 10／11環境に含まれます。初回登録でコンパイラーが見つからないと表示された場合は、.NET Frameworkを有効にしてください。

### 2. 使うサービスへログインする

両方使う場合はA・Bの両方を実施します。一方だけの利用なら、そのサービスの準備だけで構いません。

**A. GitHub Copilot**

```powershell
winget install GitHub.Copilot
copilot login
```

表示に従いCopilot契約のあるGitHubアカウントでログインします。インストール後にコマンドが見つからない場合はターミナルを開き直してください。組織契約では管理者によるCLI利用の許可が必要な場合があります。

SDKの実行ランタイムはこのアプリの依存パッケージに含まれます。CLIは主に初回ログインとモデル確認に使用します。モデルは`copilot`を起動し、`/model`で利用可能なものを確認できます。

[GitHub公式インストール手順](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)

**B. ChatGPT Business（Codex）**

```powershell
npm install -g @openai/codex
codex login
codex login status
```

**Sign in with ChatGPT**を選び、Businessワークスペースでログインします。APIキーでのログインは本拡張では受け付けません。管理者設定でCodex利用が許可されている必要があります。

既にCodex CLIがある場合も、必要な設定に対応する最新版を使ってください。`codex`を起動し、`/model`で利用可能なモデルを確認できます。普段使うCodexのログインを共有しますが、生成時はユーザーのカスタム設定を読み込まず、文章生成用の設定を適用します。

[公式Codex CLI](https://learn.chatgpt.com/docs/codex/cli)

### 3. アプリの依存パッケージを入れる

このフォルダーを置く場所を決め、PowerShellでそのフォルダーへ移動します。この環境での例:

```powershell
cd C:\React\training\backlog-ai
npm ci
```

`npm ci`は同梱の`package-lock.json`に固定された依存をインストールします。初回にはインターネット接続が必要です。

依存パッケージについて:

- Copilot SDK 1.0.27が指定する`zod`には既知の脆弱性があるため、`package.json`の`overrides`で修正版4.6.6に固定しています。SDK更新時は、この指定が引き続き必要か確認してください。[脆弱性と修正版の情報](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
- `koffi`のインストールスクリプトは、ネイティブ部品の検査と必要時のビルドを行います。本アプリのSDK接続方式では不要のため、`allowScripts`に`koffi: false`を明記しています。標準のWindows環境ではビルド済み部品も依存として配布されます。[npmのスクリプト設定](https://docs.npmjs.com/cli/v12/commands/npm-deny-scripts/)
- `npm fund`の案内は任意の寄付に関する情報で、エラーではありません。脆弱性警告が出た場合は`npm audit`で内容を確認してください。`npm audit fix --force`は、SDKを古い版へ戻して互換性を壊す場合があるため、この構成では実行しないでください。

### 4. Chromeに追加する

1. Chromeのアドレスバーに `chrome://extensions` を入力します。
2. 右上の **デベロッパーモード** をオンにします。
3. **パッケージ化されていない拡張機能を読み込む** を押します。
4. `manifest.json`があるこのフォルダーを選びます。`bridge`や`node_modules`は選びません。
5. **Backlog AI Reply**のカードが表示されたことを確認します。
6. カードの **詳細 → 拡張機能のオプション** を開きます。

### 5. 拡張機能を設定する

1. **利用するAI**でGitHub Copilot／ChatGPT Business（Codex）を選びます。
2. **モデル**で「自動選択（既定）」または取得した候補から選びます。一覧は選択中のサービスから自動取得します。再取得ボタンで更新でき、候補にないモデルは直接IDを指定できます。
3. Backlogの個人設定で発行した **Backlog APIキー**を入力します。
4. 必要なら **起動時に確認するBacklogスペースURL** に `https://your-space.backlog.com` を入力します。空欄でも、保存済みの本人プロフィールURL、最後に開いた課題のスペースの順で自動判定します。コメント取得件数を選び、**設定を保存**を押します。
5. 設定画面に表示される初回登録コマンドをコピーします。

本人情報や毎回の文体を登録する場合は、同じ画面の **共通プロンプトと本人情報** を設定し、**プロンプト設定を保存**を押します。AI・モデル・APIキーの設定とは別のフォームです。初回の共通プロンプト生成は、次の自動起動登録が済んでから実行してください。

Copilot用・Codex用のモデル設定は別々に保持します。旧版から更新すると、保存済みのClaude APIキーと旧Claudeモデル設定を削除します。Backlog APIキーとコメント件数は引き継ぎます。

モデル一覧の取得では文章を生成しません。CopilotはSDKの`listModels()`、Codexは公式app-serverの[`model/list`](https://learn.chatgpt.com/docs/app-server#list-models-modellist)を使います。一覧は候補であり、組織ポリシーや利用上限などによって実行時に使用できない場合があります。取得に失敗しても既存の選択は保持され、自動選択・直接入力で保存できます。

### 6. 自動起動を初回登録する

アプリのフォルダーで、設定画面からコピーしたコマンドを**一度だけ**実行します。管理者権限は不要です。

```powershell
npm run setup -- --extension-id ここを実際の32文字の拡張IDに置き換える
```

登録完了後、`chrome://extensions`で拡張カードの再読み込みボタンを押し、設定画面を開き直して **接続をテスト** を押します。このテストはローカル処理の起動だけを確認し、AIの認証や生成は行いません。

**登録が終わったらターミナルを閉じて構いません。** 次回からはChromeの生成ボタンだけで動作します。CLIログインは有効期限切れなどの場合を除き毎回不要です。

登録先は現在のWindowsユーザーのChrome用設定（`HKCU\Software\Google\Chrome\NativeMessagingHosts\com.backlog_ai.reply`）です。このフォルダーの`.native-host`にローカル起動用のファイルを作成し、指定した拡張IDだけを許可します。拡張IDや使用するNode.jsの場所が変わった場合は、登録コマンドを再実行してください。フォルダーを移動する場合は、移動前に旧フォルダーで`npm run unsetup`を実行し、移動先で再登録します。

旧版の`npm start`が動いている場合は、そのターミナルで`Ctrl+C`を押して終了できます。更新後はそのサーバーを使用しません。新しく追加する「ネイティブアプリケーションとの通信」権限についてChromeに確認された場合は、拡張を有効にしてください。

## 既存環境を更新する

このフォルダーで`npm ci`を実行して新しい依存を入れ、`chrome://extensions`で**Backlog AI Reply**を再読み込みします。開いている設定画面とBacklogの課題ページも再読み込みしてください。自動起動の登録済みで、フォルダー・Node.js・拡張IDが変わっていなければ再登録は不要です。

## 日常の利用方法

1. Backlogで返信したい課題の詳細画面を開きます。拡張を追加・更新した直後は再読み込みします。
2. コメント入力欄の上にある小さな **AI返信** ボタンを押してパネルを開き、送信先のAIを確認します。初期状態は折りたたまれており、ボタンは半透明です。マウスを重ねるかキーボードでフォーカスすると濃く表示されます。
3. 作成モードを選び、必要なら参照する別課題・プロジェクトを入力します。エージェントモードでは **同じプロジェクト内の他課題も調査する** のチェックで調査範囲を選べます。
4. 「修正が完了したので、確認をお願いしたい」など、今回伝えたい内容を入力し、**AIで返信文を生成**を押します。
5. 返信案が既存のコメント欄に入ります。既に文章がある場合は置き換える前に確認します。参照情報は初期状態で折りたたまれ、見出しに件数と、エージェントモードでは調査回数を表示します。見出しを開くと取得元リンクから参照内容を確認できます。
6. 事実関係・敬語・改行を確認し、Backlog側の投稿ボタンを自分で押します。

生成中はパネルに経過時間と作業ログを表示します。各行の `+0.2秒` は生成開始からそのログが画面に届くまでの経過、`所要 4.8秒` は次のログまでの時間です。待機中の最後の行は `継続 4.8秒` のように更新します。全体と各行を同じ時計で0.1秒単位で表示し、完了・失敗・挿入キャンセルの時刻で計測を止めます。ログは先頭から保持し、折りたたみや再表示でも時間をリセットしません。既存コメントの置き換え確認を待つ時間は別の行に記録し、全体の所要時間に含めます。

AIへの問い合わせ、課題・コメントの取得、取得完了など、処理の進行状況を確認できます。各区間には通信・ローカル処理の待ち時間も含まれ、AI単体の処理時間ではありません。AIの内部思考や生の応答は表示しません。生成中もカーソルは通常の表示のままで、待機カーソルには切り替わりません。

同じボタンをもう一度押すとパネルを折りたためます。入力内容を保持したまま、生成中も開閉できます。開閉状態は同じページ内で課題を移動した場合やパネルが再表示された場合も保持され、ページを再読み込みすると折りたたみ状態に戻ります。

コメント欄が画面下部に固定されている場合は、AIパネルを画面の高さの45%以内に収め、パネル内をスクロールできるようにします。コメント一覧にもパネルで増えた高さの分だけ余白を確保するため、コメント欄を開いていなくても一覧の末尾まで読めます。折りたたみ時は追加の余白を戻します。

久しぶりにタブやChromeのウィンドウへ戻った際は、拡張機能との接続を再確認します。古い接続や読み込み直後の一時的な切断は再接続し、必要な場合だけ対象のBacklog課題画面へ拡張の表示を入れ直します。AIへの生成依頼は自動で再送しません。復旧時も入力中のAIへの指示・参照先・モードとBacklogのコメント下書きを保持します。

サービスの切替は拡張の設定画面で行い、**設定を保存**します。生成ボタンを押す際にも最新の設定を確認します。生成中に課題を移動した場合は、別課題への誤挿入を避けるため生成文を挿入しません。

### Markdown記法／Backlog記法の自動設定

Chrome起動時に、保存済みのBacklog APIキーでスペースの記法設定を取得します。確認先は **起動時に確認するBacklogスペースURL**、保存済みの本人プロフィールURL、最後に開いた課題のスペースの順で決まります。URLを入力する場合は `https://your-space.backlog.com` のようにスペースのアドレスだけを指定し、課題やプロフィールのパスは付けません。`.backlog.jp` と `.backlogtool.com` にも対応しています。

設定画面でスペースの記法・確認日時を表示し、**記法を再確認** で更新できます。再確認は保存済みのURL・APIキーを使うため、入力を変えた場合は先に **設定を保存** を押してください。スペースがまだ分からない場合は、URLを保存するか、Backlogの課題画面を開きます。記法の確認はBacklog APIへの読み取りだけで、AIの契約利用枠を消費しません。

返信作成時には対象プロジェクトの設定を確認し、スペースの設定より優先してプロンプトへ反映します。通常モード・エージェントモードの両方が対象です。参照した別プロジェクトや過去コメントの記法には引きずられず、投稿先に合わせてMarkdown記法／Backlog記法を使い分けます。記法を確認できなかった場合は、その状況を作業ログに表示し、装飾を控えた文面で生成します。

生成文では宛名を独立した行にし、挨拶・回答・依頼を意味のまとまりごとに段落へ分けます。引用と回答、段落同士の間には空行を入れます。この配置指示は毎回の返信生成で適用するため、保存済みの共通プロンプトや追加指示を初期化する必要はありません。リッチテキストのコメント欄ではエディターの貼り付け処理を優先して改行を保持します。OSのクリップボードは書き換えません。

### 共通プロンプト・本人情報・毎回の追加指示

設定画面の **共通プロンプトと本人情報** で、返信する本人の表示名と、任意のBacklogプロフィールURLを別々に登録できます。URLは `https://your-space.backlog.com/user/ユーザー名` の形式で、`/user/*` も保存できます。画面の例は入力のヒントであり、自動登録はしません。

表示名を登録し、生成プロンプトを固定していない場合は、Chrome起動時にBacklogの公開公式ガイドを取得し、保存済みのAI・モデルで共通プロンプトを自動生成します。拡張の設定画面を開くだけでは生成しません。表示名が未登録なら自動生成をスキップし、取得や生成に失敗した場合は以前の生成プロンプトを保持します。生成のたびに、選択したサービスの契約の利用枠を消費します。ローカル接続の登録方法は変わらず、毎回のターミナル起動は不要です。

参照するのは公式の5記事です。「課題と状態」「お知らせ機能の概要」「プロジェクトの基本設定」は公開ヘルプセンターのJSONから、Backlog記法・Markdown記法のガイドは公開HTMLから本文を取得します。取得先はアプリ内で固定しており、AIが選んだ別のURLを読み込みません。

- **生成プロンプト**は内容を確認し、直接編集できます。**生成プロンプトを固定**をオンにして保存すると、Chrome起動時・手動の再生成を停止し、その内容を使い続けます。
- **常に追加する指示**には、毎回適用したい文体や確認事項を記載します。自動・手動の再生成では変更しません。共通の安全ルールの範囲内で、生成プロンプトより優先して適用します。
- **常に追加する指示**の初期値には、柔らかい日本語の文面テンプレートと実際の返信傾向を基にした標準プロンプトが入ります。社内では短く、社外では丁寧に、複数の質問には引用を使って順に回答し、既知の背景や不要な定型句を重ねない方針です。標準本文は `prompt-defaults.js` で管理しています。本人名や実際の取引先名・投稿内容・APIキーは標準本文に含めません。
- **デフォルトに戻す**は「常に追加する指示」だけを標準本文へ戻します。**プロンプト設定を保存**を押すと以後の返信に適用されます。本人情報・生成プロンプト・固定状態は変わりません。更新前にこの欄が未設定・空欄だった場合は初期値を適用し、既存のカスタム文は保持します。更新後に明示的に空欄で保存した場合、その空欄は維持します。
- 標準プロンプトは、返信の新規作成と自作文の整形を区別します。ChatGPTでコピーするための外側のコードブロックは付けず、Backlogのコメント欄へ挿入する完成文を出力します。記法や引用は対象プロジェクトに合わせ、本人宛てのメンションを返信先としてコピーしません。
- **プロンプト設定を保存**で本人情報・編集内容・固定状態を保存します。**保存して再生成**は未保存の編集を先に保存し、その設定で生成プロンプトを作り直します。固定中や生成中は再生成できません。
- **保存済みの共通プロンプト全体**で、共通ルール・本人情報・生成プロンプト・追加指示を合成した内容を確認できます。未保存の入力はプレビューに反映しません。生成状況、最終生成・確認日時、参照した公式ガイドも表示します。

生成中も編集・保存・固定ができます。生成開始後に設定を保存した場合、古い設定に基づく生成結果は採用しません。別の画面や自動生成で設定が更新されても、編集中の入力は保持します。保存時に競合の案内が出たら、必要な編集を控えて **保存済みを読み直す** を押し、最新の内容へ反映してください。読み直しで未保存の内容を破棄する場合は確認します。

公式ガイドの取得にBacklog APIキーは使いません。表示名・プロフィールURL・生成プロンプト・追加指示は、このChromeのローカル拡張ストレージに保存します。返信の生成ではこれらを選択したAIに送信するため、機密情報や認証情報をプロンプト欄に記載しないでください。

### 別の課題・プロジェクトを参照する

参照欄には、課題キー、プロジェクトキー、またはそれらのURLを、改行・空白・カンマで区切って入力します。現在と同じBacklogスペースの、閲覧権限がある情報だけが対象です。

```text
PROJECT-123
OTHER_PROJECT
https://your-space.backlog.com/view/PROJECT-456
https://your-space.backlog.com/projects/ANOTHER_PROJECT
```

追加指定は課題5件、プロジェクト3件までです。入力値は課題ごとにページ内メモリで保持し、ページを再読み込みすると初期状態に戻ります。

| モード | 情報の取得方法 |
| --- | --- |
| 通常の返信作成 | 現在の課題に加え、指定した課題の本文・直近コメント（各最大20件）と、指定プロジェクトの情報・更新日時順の最近の課題10件の概要をまとめて渡します。 |
| エージェント（Backlog MCPで調査） | 現在の課題を読み、AIが追加で必要な情報を判断します。設定した調査範囲内での課題検索や、対象課題の本文・コメント取得をMCP経由で行い、返信案を作成します。 |

エージェントモードの **同じプロジェクト内の他課題も調査する** は初期状態でオンです。オンの場合は、現在のプロジェクト内の他課題も検索・取得できます。オフにすると、現在の課題と参照欄で明示した課題・プロジェクトだけが対象になります。参照欄に現在のプロジェクトを明示した場合は、チェックがオフでもそのプロジェクトを調査対象に含めます。

このチェックは通常モードには影響しません。選択状態は課題ごとのページ内メモリで保持し、ページを再読み込みするとオンに戻ります。

エージェントモードでは、[ヌーラボ公開のBacklog MCP Server](https://github.com/nulab/backlog-mcp-server)の固定版`0.23.3`を同梱依存から自動起動します。Dockerや別ターミナルの起動は不要です。アプリが許可するのは`get_project`、`get_issues`、`get_issue`、`get_issue_comments`の4種類だけで、書き込み操作は実行できません。

AIによる追加調査は最大6回です。同じ取得条件の繰り返しは実行せず、取得済み情報から返信を完成させます。プロジェクトIDの解決に必要な照会は別枠で最大4件まで行います。未指定プロジェクトへの範囲拡大や、別スペースへの接続は拒否します。通常モードより複数回AIを呼ぶ場合があり、その分契約の利用枠を消費します。情報量・利用上限・タイムアウトで調査が完了しない場合は、参照先を絞って再実行してください。

## トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| AI欄が出ない | 対応ドメインの`/view/課題キー`画面か、コメント入力欄が表示されているか確認。拡張とページを再読み込み |
| 久しぶりに開いたタブで接続できない | タブ・ウィンドウへ戻る際に自動復旧。初回の更新直後や復旧しない場合は、拡張とBacklogページを再読み込み |
| ローカル接続が未登録／起動できない | 設定画面の`npm run setup`コマンドを実行し、拡張を再読み込み。Node.jsの入れ替え後は再登録 |
| 別フォルダーの登録がある | 旧フォルダーで`npm run unsetup`を実行してから、使用したいフォルダーで登録 |
| ローカル接続が許可されていない | 現在の拡張IDで再登録。会社管理のChromeではNative Messagingの管理ポリシーも確認 |
| ローカル処理が切断された | 拡張の再読み込み後に接続テスト。再発する場合は`npm ci`と初回登録をやり直す |
| SDKを読み込めない | `node --version`が22.12以上か確認し、アプリのフォルダーで`npm ci` |
| CopilotのOAuthログインが必要 | `copilot login`を実行し、契約アカウントと組織のCLIポリシーを確認 |
| Codex CLIが見つからない | CLI導入後に初回登録をやり直す。必要に応じて下記`CODEX_BIN`を指定 |
| Codexの安全設定に非対応 | 公式CLIを最新版へ更新。本アプリは安全設定を外して再試行しない |
| モデル一覧を取得できない | 接続テストとCLIログインを確認し、一覧を再取得。自動選択や直接入力でも保存可能 |
| モデル関連エラー | 「自動選択（既定）」に戻して保存。候補にあっても契約や利用上限により使えない場合がある |
| 共通プロンプトを生成できない | 表示名・固定状態・保存済みAI設定とCLIログインを確認。生成失敗時は以前の内容を維持。公式ガイドに接続できる状態で「保存して再生成」を実行 |
| プロンプト設定の保存が競合する | 編集内容を控え、「保存済みを読み直す」で最新の内容を読み込んでから編集を反映 |
| 利用上限・タイムアウト | 契約の使用状況を確認。コメント件数を減らして再試行。AI処理は最大3分、取得・接続を含む全体待機は最大4分 |
| Backlog 401／403 | Backlog APIキーと対象課題の閲覧権限を確認 |
| 記法を確認できない／スペースURLが未設定 | スペースURL・Backlog APIキーを保存し、「記法を再確認」を実行。URLを空欄にする場合は本人プロフィールURLを保存するか、Backlogの課題を開く |
| 課題情報が長すぎる | コメント件数や追加参照先を減らす。送信内容には160,000文字の上限がある |
| 追加参照やMCP取得が失敗する | 同じBacklogスペースか、キーが正しいか、対象の閲覧権限があるか確認。MCPパッケージのエラーは`npm ci`で依存を再導入 |
| 生成したが挿入されない | 入力欄が表示されているか確認。Backlogのエディタ構造変更で調整が必要な場合がある |

Codexを任意の場所にインストールしている場合は、初回登録時に実行ファイルの**絶対パス**を指定できます。

```powershell
$env:CODEX_BIN = 'C:\実際のインストール先\codex.exe'
npm run setup -- --extension-id 実際の拡張ID
```

npm版の公式`codex.cmd`または`codex.js`の絶対パスも指定できます。認証ファイルを拡張のフォルダーにコピーしないでください。

## 更新方法

ソースを更新したら`npm ci`と初回登録コマンドを実行します。`chrome://extensions`で拡張カードの再読み込みボタンを押し、Backlogの課題画面も再読み込みしてください。

## 自動起動の登録を解除する

Chromeで拡張を無効にしてから、アプリのフォルダーで実行します。

```powershell
npm run unsetup
```

このフォルダーを指すChromeの登録を解除します。別の場所にあるアプリの登録や、GitHub／ChatGPTのログインは削除しません。アプリのフォルダーを削除する前に実行してください。

## データと権限

- Chromeに登録した拡張IDと、起動時の呼び出し元を検査します。一般のWebサイトから直接起動できるHTTPサーバーは使用しません。同じPC上の悪意あるプログラムに対する隔離機構ではありません。
- 拡張の権限は対応Backlogドメイン、Native Messaging、設定保存と、接続復旧時に拡張自身のスクリプトを読み込み直す `scripting` です。復旧対象は対応Backlogドメインの課題詳細画面に限定します。
- AIプロバイダーが持つファイル・シェル等のツールは無効のままです。エージェントモードではアプリがAIの判断を受け取り、許可したBacklog MCPの読み取り操作だけを実行します。Codexは読み取り専用設定も適用します。これはプロバイダー全体をOSレベルで隔離する仕組みではありません。
- 課題情報と生成文はローカル処理のメモリ内で扱い、完了後に接続と処理を終了します。本文をログ出力しません。プロバイダー側の保存・取り扱いには各契約のポリシーが適用されます。
- 本人情報・生成された共通プロンプト・毎回の追加指示は、Chromeのローカル拡張ストレージに保存します。返信生成時はこれらも選択したAIへ送信します。共通プロンプトの再生成時は、公開公式ガイドと本人情報を送信し、課題データやBacklog APIキーは送信しません。
- Backlog APIキーはローカル拡張ストレージに保存します。エージェント実行時だけNative Messagingでローカル処理へ渡し、MCP子プロセスの環境変数として使用します。起動引数・AIの入力・設定ファイルには書き込みません。Backlog API仕様によりリクエストURLに含まれるため、ネットワークログを共有する際は注意してください。
